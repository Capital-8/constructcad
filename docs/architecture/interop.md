# Architecture: IFC, CAD, SketchUp, OBJ and glTF

Part of the architecture notes indexed in [AGENTS.md](../../AGENTS.md). Keep each topic in its bullet here; AGENTS.md only lists the topics.

- **cc_ifc** — IFC4 export with an in-house STEP writer (`step.rs`) and IFC2X3/IFC4 import with an in-house STEP parser (`parse.rs`, bounded nesting), geometry engine (`geometry.rs`: placements, curves, profiles, swept/CSG/B-rep/face-set items → world polygon meshes, depth- and size-bounded) and mapping (`import.rs`); no third-party IFC libraries by design. Import never drops a physical class: products become native elements only when a native element holds their geometry exactly (types matched by name and size; GlobalIds kept as `Uid`s), slabs become floors (with `Floor::openings` from profile voids and from openings that pass through them vertically) or, as base slabs shaped like slabs, foundation slabs (piles and pile caps written as base slabs stay components); anything else (including coverings, roofs, columns and beams voided by openings) becomes a component with `Mesh` pieces whose `ComponentDef::ifc` keeps the class and the type's property sets (`cc_core::properties`, values in SI units; instance sets live in `Component::properties`; objects of one name share a type only when their pieces and class are the same, and a type-less object whose placement lies outside its body is placed at the bottom center of its body, so identical objects written in world coordinates share one; `tests/rebar.rs`), with its openings subtracted by `csg.rs` (arena BSP-tree booleans, iterative and budgeted; also used for boolean results); `schema.rs` (IFC4 attribute layouts and type objects per element class) lets export write that class back. Column and beam types write their structural profile (`Exporter::profile_def`: the parametric `Ifc*ProfileDef` with its box centered on the position and the type's turn as its direction, else the placed outline as an arbitrary profile; a lipped Z has no IFC shape; an annular sector with a hollow is its outline with its two arcs, `sector_curves` through `curve_loop`, checked against the placed outline by `on_outline`, and its quantities take the exact area) in an `IfcMaterialProfileSet` per type and an `IfcMaterialProfileSetUsage` per element; level square-ended profile beams are swept along their axis, plain rectangles stay boxes, other beams faceted B-reps. Import reads columns and beams extruded from any profile (`Geometry::parametric_shape`, else an outline of two concentric arcs joined by radial sides as an annular sector placed by its ring (`ring_sector`, `rounded_sector`), else the outline as a sketch of literal points, else its box; `Importer::profile_for` reuses a profile of the same name and shape). `tests/round_trip.rs` checks export → import. Tanks from other programs (`tests/tank.rs`, everything in world coordinates with no axes or types): `ring_sector` reads a profile of two concentric arcs joined by radial sides, which `import_column` turns into `ProfileShape::AnnularSector` placed by its ring (values rounded to 0.01 mm and 0.001°, so the columns around a ring share a profile and a type) and `import_beam` into an arc beam on the middle circle when the body has no axis; a `BASESLAB` keeps its profile's curves as `Foundation::sketch`; `import_pile` falls back to the construction type; `foreign_partition` reads a property named Partition (several languages, accents ignored) into a shaped bar set's `partition`; `ShapedRebar::MAX_BARS` is 20,000 with `MAX_TOTAL_POINTS`. `import_bar` takes the bar type its IFC type object names, else `Importer::nominal_bar_type` (the project's bar type of the nominal diameter within 0.05 mm whose grade, letters and digits compared, is the bar's or empty, but not empty when the grade is this program's own `Grade` in `REBAR_PSET`, a type's grade; the same grade first), else makes one with the file's `SteelGrade` as its `grade`; a purely numeric `Tag` (another program's element id) is no mark unless the bar carries `REBAR_PSET` or the file is this program's (#369, `tests/foreign_bars.rs`). Curved outlines (#368, `tests/curved_profiles.rs`): floors, foundation slabs, ceilings and flat roofs without overhang whose sketch has arcs or circles and still draws them (`curve_profile`, over `Sketch::curve_profile`: the loops' curves in order, outline counter-clockwise, openings clockwise) are written by `Exporter::extrude_curves`: a lone circle as an `IfcCircleProfileDef` at its center, else `curve_loop` composite curves (straight runs as `IfcPolyline`s, each arc an `IfcTrimmedCurve` of its `IfcCircle` by its end points, `CARTESIAN`, the sense its turn; a circle two halves; ellipses and splines their points; every segment `CONTINUOUS`), shafts' cuts as polylines; import reads a trimmed circle as one arc (`Geometry::circle_arc`, by parameter or point, either sense; full turns a circle), arcs of one circle going all the way round as the circle (`whole_circle`), and gives ceilings and flat roofs their sketch too (`Importer::curved_outline`). Bar sets (#368, `tests/bar_sets.rs`): a `Rebar` set also writes its host's GlobalId (`Host`) and itself as text (`Layout`) in `REBAR_PSET`; import brings it in as shaped bars, then `restore_bar_sets` (when the import ends, before `repair`) makes it the native set of the imported host when `Rebar::is_valid` and `Project::rebar_host_fits`, and `check_bar_sets` (after `repair`) puts the shaped bars back unless the set laid out again has as many bars within a diameter and a centimeter of their bounds; this program's stirrups, written a diameter short of closing (`directrix`), are closed again on import (`close_stirrup`), so shaped bars keep their length. `IFCPROJECT`'s `Name` is the project number and `LongName` its name (with only one of them, or both equal, it is the name); export writes them so (#369). Every other product's mark is its `Tag` (`Importer::mark`), except a purely numeric one in a file another program wrote: `StepFile::originating_system` (from `FILE_NAME`) not starting with ConstructCraft or ConstructCAD (`written_here`); empty address lines are left out of the project address (#436, `tests/foreign_tags.rs`). Curved walls and footings of other programs (#370, `tests/curved_elements.rs`): `ring_band` reads a band of a ring from plan curves (two concentric circles, a full ring; or arcs on two radii turning opposite ways through the same angle, split arcs included, joined by two radial sides: `start` and `sweep` counter-clockwise; `ring_sector` is the band within a profile's limit), and `ring_arcs` splits it into native arcs on its middle circle, clockwise (a wall's exterior side, its left, faces out), one arc or two halves past `MAX_BULGE` (a full ring is two half circles, met end to end). `Importer::ring_wall` makes arc walls of a vertical extrusion of such a band (an `IfcCircleHollowProfileDef`, a profile with a circular void, an annular sector outline), only when every opening voiding the wall is filled by a door or window (the fillers take the piece their middle projects into, `wall_piece`; `walls` maps an IFC wall to its pieces). `geometry::Solid::revolution` keeps a single closed profile revolved (`Revolution`: profile, plane, world axis and signed turn; `section` gives the outline as distance from the axis and height along it when the plane holds the axis and the outline stays clear of it). `import_footing` dispatches `IfcFooting`s: this program's pile caps (`import_pile_cap`); others' `PILE_CAP`s wait in `foreign_caps` until every pile is in (`import_foreign_caps`, after `link_piles`); `footing` makes native strips of `strip_of` (also this program's own haunched strips, which export writes so: `Exporter::strip_sweep`, #435) (a `StripSection` from `strip_section`: a rectangle or the outline a `StripHaunch` draws, corners matched within `SECTION_TOL`; revolved about a vertical axis by `revolved_strip`, a ring extruded upwards, or, for `STRIP_FOOTING`, a plan rectangle extruded upwards or a section extruded level and square to its plane) in a strip type found or made by width, thickness and haunch (`add_strips`), and native pads of `PAD_FOOTING` plan rectangles (`import_pad`, a named type the other way round turns the pad a quarter). `foreign_cap` reads a `CapShape` (`cap_shape`: rectangle, disk, full ring extruded or revolved), takes the free piles whose axes are inside it and heads within it (one type, length and head), tries the layouts that outline can hold for that many piles (single, pair, square, line; circle round a disk; circle with `ring_width` on a ring's middle circle; edge distance, spacing and embedment from the outline and piles, rounded to 0.01 mm so caps alike share a type; `problem` and `repair` clean) and keeps the first whose positions meet every pile within a millimeter: a native cap whose type names the piles' type, the piles linked to it by index as `cap_piles` wants them (so `sync_piles` changes nothing); otherwise a ring is ring strips and anything else a component. `slab_sketch` keeps the curves of each opening (`Extrusion::footprint_curves` of a cut or voiding opening), and with a curved opening builds the sketch even when the outline is a polygon, so a circular hole stays a circle. Not read: sweeps along arcs (`IfcSurfaceCurveSweptAreaSolid` and the like), composite profiles, round pads (no native round pad) and triangular caps. Walls attached to a roof, ceiling or floor (`Wall::attach_top`, straight walls only; see `attach_wall_tops`) export their extrusion up to the top's highest point (or each layer's item of a banded wall) cut by a half space per stretch of `WallGeom::top_profile` (`top_cuts`: segments merged where one line runs on, those at the body's top left out; the plane through the stretch, level across the wall, so the body is the app's and matches the target's face wherever that slopes along the wall, as under a gable), nested `IfcBooleanClippingResult`s with representation `Clipping` (`Exporter::top_half_spaces`, `clip_by`): an `IfcHalfSpaceSolid` where the plane runs nowhere below the top, else an `IfcPolygonalBoundedHalfSpace` bounded to its stretch (past the wall's faces, and its ends at the top's ends); a top that drops to the base or leaves gaps is not cut. `Qto_WallBaseQuantities` takes `Height` and `GrossSideArea` from the top (`top_face`; `NetVolume` is the geometry's). The geometry reader subtracts a bounded half space that covers only part of its operand as its boundary's prism clipped by its plane (`Geometry::bounded_half_space`), and import reads a straight wall whose one extrusion is cut by faces level across it as a wall with an elevation profile of that top (`clipped_top`; `tests/attached_walls.rs`); the attachment itself does not come back, nor the cut top of a banded wall (rebuilt from `ConstructCAD_WallLayers`). GlobalIds come from `Uid`s; derived objects (relationships, openings) hash the project uid with a tag. Roofs a roof join changed (joined, or cut by a joined wing; `ModelGeometry::roof_joins`) are written as the faceted B-rep of their solid whatever their shape (`write_pitched_roof`), `Qto_RoofBaseQuantities` from the join's `plan_area` and `sloped_area`, with `ROOF_JOIN_PSET` (`ConstructCAD_RoofJoin`: `Joined`, and `JoinedTo` the GlobalId of the roof it is joined to; inactive joins are written too, with `Joined` false); import keeps a roof whose `Joined` is true as exact geometry (a component of the `IFCROOF` class: the join is not rebuilt), so its aggregated framing members are imported as objects (`framed_roofs` is only filled by native roofs).
- **Imported CAD drawings** — `cc_core::cad` holds the neutral drawing (`CadDrawing`: layers with RGB colors and file visibility, flat `CadPrim`s in drawing units — polylines with bulges, arcs kept as arcs, single-line texts with alignment, fills — extents and declared units) and the element `ElementKind::CadImport(CadImport)` (category `CadImport`, a `TypeData::CadImport {}` type created with the first import): owned by one view (`view`, like text notes; plans, ceiling plans, elevations, sections and legends, see `cc_views::hosts_cad`) and placed by `units`, `scale`, `position`, `rotation_deg` and `mirrored`, with `hidden_layers`, `color_mode` and `halftone`. The drawing is an `Arc` so undo steps and the repair check do not copy it; `repair` drops invalid primitives (copying only when needed), and the element has no phase. **cc_cad** reads files into it: an in-house DXF reader (`tokens.rs` ASCII/binary group pairs and code pages, `dxf.rs` sections/LAYER table/BLOCKS/ENTITIES, model space flattened while read, `flatten.rs` OCS → world with the arbitrary axis algorithm, nested/arrayed inserts with a cycle guard, depth, primitive and work budgets, layer 0 and BYBLOCK inheritance, `geom.rs` ellipses and de Boor splines, `text.rs` MTEXT codes); DWG goes through the `acadrust` crate (no default features, read from a byte buffer) on its own thread inside `catch_unwind`, its document written to binary DXF in memory and read by the same reader. `cc_views::cad` draws an import in its view under everything (thin lines with their own `Pen`, tessellated for the view scale), and `Drawing2D::background` makes `hit_test` pick it only where nothing else is; `graphics::apply` merges overrides into a line's own pen. `cc_engine::commands::cad` holds `cad_import`, `cad_layers` and `cad_layers_set`; `cc_engine::commands::cad_explode` holds `cad_explode`, which turns an import's visible primitives (`CadImport::layer_visible`) into native elements of its view through its placement in one undo step: polyline segments (bulges as arcs, negated under a mirror) and arcs (split past 270 degrees, circles as circles) become `DetailLine`s on a `LineStyleRef::Project` style per layer (found by name, else created with the layer's `cad::on_paper` color), fills boundary-less `FilledRegion`s of a solid type per color, texts `TextNote`s (top left 1.25 sizes above the baseline) of a `TypeData::Text` per size on paper (tenths of a millimeter), and visible pictures stay in the element (prims emptied; removed when none); `MAX_ELEMENTS` and `MAX_NEW_TYPES` refuse it before any edit, and the color mode and halftone are dropped (app: `UiCommand::Explode` on the Modify tab and the *Explode* button in `cad_ui::props`); `element_get`/`element_set` show and patch the placement without the drawing (`cc_engine::element_params`). Pictures share the element: `CadDrawing::images` holds `CadImage`s (a parallelogram `origin`, `u`, `v` in drawing units over a `cc_core::raster::RasterImage`: the file's own bytes, kept as base64 in project files, with format, pixel size and declared dpi), `cc_views::raster` reads sizes and decodes pixels (the `image` crate, size-bounded), `cc_views::cad` draws them as `Prim::Image` (under everything, faded with the element; `Prim::mapped` moves any primitive through an affine map), the app paints them as textured quads cached per picture (`paint.rs`), and exports write them (SVG `<image>` data URLs, PDF image objects with an alpha mask, PNG through resvg). `cc_cad::svg` reads SVG through usvg into the same drawing (curves flattened, single-outline fills, embedded pictures; texts skipped); `image_import` takes either and sizes pictures by their resolution or `width`. The app's tools snap to `CadImport::snap_features` (ends, midpoints, centers, lines, arcs) of the active view's imports; IFC export and 3D views ignore them.
- **cc_skp** — SketchUp (.skp) files, no external dependencies (its own ZIP, inflate/deflate and earcut). `SkpFile::open(..).parse(&ParseOptions)` gives an `SkpModel` (definitions, instances, faces, edges, materials, layers, pages; lengths in inches) from the current (ZIP) and legacy (version 3 to 2020) formats; `build_scene` flattens it to triangle meshes and `build_instanced_scene` keeps one mesh per definition plus placed nodes; `create::SkpBuilder` writes files and `edit::open_existing` rebuilds a builder from one. Derived from MIT-licensed code: the crate keeps `license = "MIT"` and its `LICENSE`. `cc_engine::skp` maps a parsed model to component types of fixed `Mesh` pieces (one per material, faces with holes triangulated): `skp_import` adds an element per placed component or group of the root (instances that differ only by a move or a plan rotation share a type; tilt, scale and mirror are built into the type; nested instances are flattened into their parent; the root's loose faces make one more element), `skp_component_load` makes the whole file one type; hidden objects and hidden layers are left out, materials are matched or added by name, and nesting depth and face count are bounded. `cc_engine::obj` reads Wavefront OBJ text into the same `skp::Converted` (in-house parser: `v`, `f`, `o`/`g`, `usemtl`, `mtllib` read by file name only next to the file, `Kd` colors; bad indices drop the face, bent faces become triangle fans, sizes bounded): `obj_import` (`units`, `z_up`, `merge`) places a type per object at the center of its footprint and its bottom; the app asks for those options in `obj_ui.rs` (*Insert → Import OBJ…*). Imported materials (`cc_engine::import_material::ImportedMaterial` in `Converted::materials`: name, color, opacity, texture) carry SketchUp textures (tile size in inches), OBJ `Kd` (read as sRGB), `d`/`Tr` and `map_Kd`, and glTF base color, `baseColorTexture` (buffer view, data URI or file beside; WebP source) and blended alpha; the color is the factor times the picture's average (`average_color`, linear), and the repeat the area-weighted meters per texture coordinate unit (`UvScale`), since textures are laid on face planes. Imported mesh pieces (SketchUp, OBJ, glTF, IFC) have their coplanar faces merged by `cc_geom::coplanar::merge`: neighbors across shared edges in one plane (1°, 0.01 mm) grow into one simple polygon, joining only along one run of edges so no hole or pinch forms; `Face::triangulate` splits a concave quad along its inner diagonal. `cc_engine::gltf` reads glTF 2.0 (`.glb` chunks, or `.gltf` JSON; buffers from the binary chunk, base64 data URIs or files by name only next to the file) into the same `Converted`: each root node of the scene with its descendants (node transforms composed, a depth limit and a visited set) is an object, triangles (modes 4 to 6, float or normalized integer positions, every offset and count checked) are turned from Y up to Z up, materials named with their base color as sRGB; primitives with `KHR_draco_mesh_compression` are decoded from the extension's buffer view (`Walker::draco`, attributes by the stream's unique ids, one decode per buffer view per import) and required meshopt compression is refused; `gltf_import` (`merge`) places them like `obj_import` (`place_converted`), `gltf_component_load` loads a file as one reusable component type (origin as insertion point) with optional `kind`, `ifc_class` and `properties` (IFC property sets), and `obj_ui.rs` serves *Insert → Import glTF…* too, asking only `merge`.
- **cc_rvt** — Revit project files (.rvt) through the crates.io `rvt` crate (rvt-rs, Apache-2.0, pure Rust, `forbid(unsafe_code)`; it brings `cfb`, `flate2`, `quick-xml` and `clap`, which only its own binaries use, so `clap` adds build time but no code to ours). **Optional:** `cc_engine`'s `rvt` feature (and `cc_app`'s and `cc_cli`'s, which turn it on) is off by default, because the reader is reverse-engineered and its clean-room claim is its own; without it `rvt_import`, *Import Revit…*, the home button, `.rvt` in Open, drops and `ccad -p`, and `ccad rvt-to-ifc` do not exist, and release builds (`-p cc_app -p cc_cli`, default features) do not compile `rvt`. `cc_rvt` stays a workspace member, so `--workspace` builds and tests it. **Child process:** a damaged file may make the reader panic, overflow its stack or run without end, and a stack overflow aborts the whole process, so `cc_rvt::convert_in_child(&Converter, input, timeout)` runs the conversion in another process: `Converter { program, args }` plus `<file.rvt> <out.ifc> <report.json>`, in a fresh `constructcraft-rvt-<random>` folder under the temporary folder (deleted afterwards), stdin and stdout null, the last 8 KiB of stderr kept; it polls `try_wait` and kills the child after `timeout` (`RvtError::Timeout`); a child that ends without a report is `RvtError::Crashed` (its last stderr line, such as `fatal runtime error: stack overflow`, or its exit status), one that cannot start is `RvtError::Process`. A `stop` callback, checked every tick, kills the child when it returns true (`RvtError::Cancelled`); `rvt_import` passes `Session::stop_requested`, so a stop flag set from another thread (`Session::set_stop_flag`; the app's `jobs::cancel`) ends the conversion with an `ErrorCode::Cancelled` error (`job-cancelled`). The child side is `cc_rvt::child_main(args)`, which `ccad` and the app call when their first argument is `cc_rvt::SUBCOMMAND` (`rvt-to-ifc`), read with `args_os` before anything else; it writes the IFC and a report, the JSON of `Result<Summary, RvtError>` (`{"Ok": …}` or `{"Err": …}`), to the report path or standard output, and exits 0, 1 or 2 (usage). `cc_engine::rvt` holds the converter `rvt_import` runs (`set_converter`; by default `Converter::this_program()`, the running program with `rvt-to-ifc`) and re-exports `child_main` and `SUBCOMMAND`. **Conversion** (in the child): `convert_file` refuses a file over `MAX_RVT_BYTES`, opens it with `RevitFile::open_bytes_with_limits` (default `OpenLimits`), builds the model with `rvt::ifc::run_export_with_limits` (`ExportOptions::default()`, which is `rvt-ifc` with no switches, and default `WalkerLimits`) and writes it with `step_writer::write_step_to`, on its own `rvt-reader` thread (128 MiB stack) inside `catch_unwind`, so a panic is `RvtError::Internal` in the report; a model a resource limit kept from being read whole (`ExportDiagnostics::is_partial`) is refused (`RvtError::Partial`), as `rvt-ifc` refuses it. `Summary` has `revit_version`, the building elements written, those with a body, `boxes` (bodies that are their element record's bounding box, `ExportedModelDiagnostics::bounding_box_bodies`) and the converter's notes and warnings (English, from the crate); `Converted` is the IFC text and the `Summary`. **Command:** `cc_engine::commands::io::RvtImport` (`rvt_import`, a `File` command, registered under `#[cfg(feature = "rvt")]`; `registry!` takes attributes before a command) refuses files over `MAX_RVT_BYTES` before starting the child, converts with `timeout` (seconds, default `cc_rvt::DEFAULT_TIMEOUT`, 600), imports the text with `cc_ifc::import` into `new_project()` and returns `ifc_import`'s report (`import_report`) plus `revit_version` and `converted` (with the notes' text); `From<RvtError> for EngineError` gives `err-rvt-read`, `err-rvt-partial`, `err-rvt-timeout`, `err-rvt-crashed` and `err-rvt-converter`, a translated sentence with the English detail in parentheses, as `err-ifc-parse`. `docs/commands.md` is the default build's reference (`reference_is_current` is ignored with the feature). The converter tags each element's body source in an `RvtElementRecordGeometry` property set (`BodySource`, `SectionWidth`, `SectionDepth`…), which generic components keep. Known converter limits seen on a Revit 2024 project: every beam drawn along its axis (`partition_beam_axis`) got a 0.2 × 8.3 m section whatever its type, the depth being its record's bounding-box height (a wall-sized sheet), and windows from saved meshes that stay generic. App (feature `rvt`): `UiCommand::ImportRvt` (*Insert → Import Revit…*, also on the home screen), `actions::open_path` and drops take `.rvt` (`actions::OPENABLE`, with `file-filter-openable-rvt`), and the status message adds `msg-rvt-boxes` and `msg-rvt-notes` (the notes' count; their text stays in the command's JSON). `ccad -p file.rvt` imports it. Tests: `cc_rvt` unit tests over a synthetic file from rvt-rs's `gen-fixture` (`tests/fixtures/synthetic.rvt`: conversion, other files, damaged prefixes and flipped bytes, and the child process: a conversion, a refused file, a converter that never ends, one that overflows its stack, one that cannot start); `cc_engine/tests/rvt.rs`, `actions::tests::rvt` (opening a file; a truncated file opened and a corrupted one dropped keep the open project) and `cli::revit_files_are_converted_in_a_child_process`. Tests run their own test binary as the converter: an `#[ignore]`d test that calls `child_main` on the arguments after `--`, started with `--exact <test> --ignored --quiet --`. CI's `rvt` job runs clippy and these tests with the feature on Linux.
- **Draco** — `cc_engine::draco` wraps the crates.io `draco-core` (pure Rust, Apache-2.0; default features off: encoder, decoder, valence EdgeBreaker and legacy decode, no point-cloud paths). `encode(positions, normals, uvs, indices)` quantizes positions to `POSITION_BITS` (16, over each mesh's extent), normals to `NORMAL_BITS`, UVs to `UV_BITS`, at speed 4, deterministic, and returns the stream with the encoded point and face counts and the attributes' unique ids (`Encoded`, for the glTF accessors); `decode(bytes)` gives a `Decoded` (points, triangles, every attribute of 1 to 4 numbers with its normalization) under `DecodeLimits` (`MAX_POINTS`, `MAX_FACES`, `MAX_DECODED_BYTES`) with every face index checked. Both run behind `catch_unwind` (a crafted stream or a codec bug is `None`/`Err`; the app's panic hook still logs it). Cache: `set_cache_dir` (process-wide `RwLock`, so worker-thread imports use it; the app sets `<data dir>/draco-cache` in `main`, the CLI and tests none) makes `decode` go through `decode_cached`: entry `<sha256 of stream>.drcmesh` = `CACHE_MAGIC`, the stream's SHA-256, the SHA-256 of the body, the body (counts, indices, attributes as f32); used only when both hashes match and every count is in bounds and the body is read exactly, else removed, decoded again and rewritten (written to a temp file then renamed); streams under `CACHE_MIN_STREAM` are not kept; `trim` deletes the oldest entries past `CACHE_MAX_BYTES`. The hashes guard against damage, not against someone who can write the folder. Tests: unit tests in `draco.rs` (round trip, refusals, truncated and flipped streams, cache hit, damaged/foreign entries, trim), `gltf_export::draco_compresses_the_meshes_and_reads_back` and `gltf::bad_gltf_files_are_errors`.
- **glTF export** — `cc_engine::gltf_export::export(project, geom, view, draco)` writes a `.glb` (JSON chunk + one binary buffer) of the solids a 3D view shows, through `cc_views::graphics::Resolver` (hidden elements left out; masses and pieces not shown at the view's detail level skipped), from the view's geometry (`Session::view_geometry` / `geom_for`: phase and design options). Layout: scene roots are levels (ordered by elevation, a `No level` node for the rest), children one node per element `<type> [E<id>]` with `extras` {id, uid, category, type, mark, level}, a mesh per element with one primitive per material (`MaterialKey`: a project material by name, else `Color RRGGBB`; painted faces use the paint's). Model (x, y, z) → glTF (x, z, −y); triangles re-wound to the face's outward normal; normals from `Solid::vertex_normals`, UVs as the path tracer lays them (`texture_uv` with `facet_shifts`) for textured materials, meters along `plane_axes` otherwise, whole repeats taken off per face. Materials: metallic-roughness from the appearance (the path tracer's roughness table, metal for class `Metal`, `BLEND` below full opacity, glass at least 0.5 transparent or of class `Glass`, opacity 0.3 when it has none), `doubleSided`; PNG/JPEG textures embedded as they are, other formats re-encoded to PNG (`png` crate), at most `MAX_TEXTURES`. With `draco`, each primitive is `crate::draco::encode`d (`Writer::draco`): the stream in a buffer view without target, accessors with no `bufferView` (POSITION with min/max from the original positions, NORMAL, TEXCOORD_0, indices of `faces * 3`), the extension on the primitive and `KHR_draco_mesh_compression` in `extensionsUsed` and `extensionsRequired`. Output is deterministic (same model, same bytes); refused past `MAX_TRIANGLES`. Command `gltf_export` (`io.rs`, `CHECKS_PATHS`: plugins use it with a granted `save_path`; `draco`; returns `bytes`); the app's *Export glTF…* (`UiCommand::ExportGltf`, `gltf_export_ui::open` picks the file, then its dialog asks for Draco, remembered in `Dialogs::gltf_draco`, and exports the active 3D view or the first). Tests: `crates/cc_engine/tests/gltf_export.rs`.
